1 Introduction

  • Initially developed as Batched Abstraction Modelling (BAM) for the Environment Agency at Wood
  • Re-written and enhanced into the Scenario Assessment Tool (SAT) at Stantec

2 Idea

"Innovate current groundwater modelling methodologies by combining Stantec’s modelling capabilities with the use of scientific programming. YAY!"

  • Create a flexible system that automates the setup and running of multiple model scenarios and compares them to a given baseline
  • Unlike BAM, scenarios in SAT can contain specific abstraction rate changes (or switch-offs) and can include multiple abstractions per scenario
  • see PQQ document for full context

3 Golden Paragraph

"The SAT tool is designed to automate the setup, running and post-processing of multiple model scenarios which are subsequently compared to a given baseline. Model runs are automatically simulated in sequential order and can be run in parallel providing an efficient way to complete a great number of scenario runs in a short time. This approach also provides a more error proof process for model setup and processing as all steps are coded and simply repeated for each scenario thus assisting with and reducing the necessary post QA effort. The idea behind SAT is to innovate current groundwater modelling methodologies by combining Stantec’s modelling capabilities with the use of scientific programming."

4 Methodology

In short:
It keeps a list of abstractions scenarios (2 - see img below) on the server (master) to be accessed by each of the model machines processes (nodes).
Each node will update a progress file (1 - see img below) on the server to keep track of which scenario is next.

Basic workflow:

  1. Find the next scenario which needs running (from progress file)
  2. Gather abstraction information for that scenario (from scenario spreadsheet)
  3. Write the scenario WEL file (using those rates)
  4. Run the MODFLOW model scenario
  5. Extract the required post-processing output (for specified locations and time periods)
  6. Produce impact assessment data and figures (compare scenario and baseline)
  7. Report back to master process that current scenario is finished (progress file)
  8. Repeat the process

5 How to SAT - quick manual

How to set up and run SAT
1st: Check you are using the latest versions of the SAT python scripts.

5.1 Create the scenario spreadsheet

  • This is a CSV file with the list of scenarios which lives on the server (all SAT nodes need access)
  • Example spreadsheet and CSV are in the the master folder
  • Header comments of XLSX-file tell you what is needed
  • When finished convert to CSV and provide link in setup (see SETUP below)

5.2 Create the folder structure

  • Place SAT node folder structure (see diagram below) on the model machine of your choice - see example in this folder
    • .\MF\baseline recommended (not required) place for all MODFLOW files from the baseline run (see SETUP below)
    • .\MF\S.. will be created by SAT according to the run mode selection (keep/overwrite)
    • .\MF_work_files needs to include:
      • MODFLOW template NAM file (used by SAT to create SAT_scenario.nam)
        • SAT will take the first file with ending .nam
        • Should include valid paths to the model input files (these are unchanged in scenarios)
          • NOTE: SAT_scenario.nam will live in .\MF\Scenario\work i.e. relative paths in template NAM need to be 3 additional folders below (..\..\..\)
          • WEL file will be created in .\MF\Scenario\input and linked automatically in SAT_scenario.nam
          • all files going to ..\output (check spelling/casing) will be named SAT_scenarioXXX.XXX
      • MODFLOW executable and associated DDLs
      • runScenario.bat runs 1st MF and then the selected PP tools (needs to be created, see examples)
    • .\PP Create a subfolder for each post-processing output needed (as selected in SETUP), containing executable and template control file, folder names must be:
      • \PP\headtime for GW head time-series
      • \PP\flowtime for SW flow time-series
      • \PP\headspatial for spatial heads plots (uses defined SPs - see SETUP below)
      • \PP\flowspatial for spatial flows plots (uses defined SPs - see SETUP below)
      • \PP\gwswtime for GW-SW time-series
    • Note: When creating template control files, don't forget the ever lurking 80 char limit (apparently a coding standard dating back to IBM's 1928! punch card) - use relative paths!

Node Folder Structure - Setup

NODE
      |
      +-SAT.ctl                -SAT control file (written by script)
      +-RUN_SAT_Vxxx.py        -SAT python script
      |
      +----MF
      |    +----baseline       -recommended folder for MODFLOW input and output files from SAT baseline run
      |    +----S0X            -SAT will create this: folder per scenario (if option 'keep') or single folder (if option 'overwrite')
      |         +----input     -SAT will create scenario WEL file(s) here
      |         +----output    -SAT scenario runs will store output here
      |         +----work      -SAT will create scenario NAM in here (all other MF files copied from MF_work_files
      |
      +----MF_work_files       -contains: Template NAM file, MODFLOW executable + libraries, runScenario batch file
      |
      +----PP
           +----headtime       -contains: executable (e.g. Gwlevels.exe) and template ctl file
           +----flowtime       -contains: executable (e.g. strflowu.exe) and template ctl file
           +----headspatial    -contains: executable (e.g. hedaview_v2.exe) and template ctl file
           +----flowspatial    -contains: executable (e.g. streamxy_nopause.exe) and template ctl file
           +----gwswtime       -contains: executable (e.g. strleak.exe) and template ctl file


5.3 SETUP: Open GUI (SAT_GUI.py)

GUI provides tooltips on hover

  • Run specification:
    • Run type:
      • Full run: Run MODFLOW scenarios as listed in scenario spreadsheet and selected post-processing
      • Post-processing: Run only post-processing on the scenarios (assumes scenario output files already exist)
    • Number of scenarios:
      • Type 'all' to run all scenarios listed in scenario spreadsheet
      • Use single integer to run a specific scenario
      • Use slice e.g. 2:5 to run a subset, in this case scenario 2 to 5
  • Model specification
    • SP/month: Used for WEL calculations (abstraction profile is repeated for each SP)
    • Output SPs: For spatial heads/flows plots. This can be one SP or multiple (comma separate list)
  • Run mode
    • Overwrite: SAT nodes only keep one output folder and overwrite former runs (after extracting post-processing results)
    • Keep: SAT nodes create an output folder per scenario
  • Master Files (all SAT nodes need access to these)
    • Scenario spreadsheet: CSV file as create above
    • Progress file: Scenario run record. Will be created by 1st node.
  • Baseline model file paths:
    • Baseline model files are used as:
      • WEL: starting point for scenario WEL files
      • BAS, HDS, STR & CS1: post-processing of scenario impact
  • Select desired PP output and output folder paths
    • check the boxes to select the PP you want
    • define where you want the PP results to be saved
    • SAT will create output folders for baseline, scenario and impact (difference) within those
  • Press SAVE & CLOSE button to save settings to SAT.ctl (same folder)
  • Settings are loaded automatically from SAT.ctl at start of GUI

5.4 RUN SAT

  • Press SAVE & RUN button to run this specific node to either:
    • Start a new SAT run (will create a new progress file)
    • Join an existing SAT run (if progress file already exists)
  • This will run the SAT workflow until all runs are done

NOTES:

  • Make sure to use the same MF executable for the SAT scenario run as used for SAT baseline run
  • Check progress file (.PRG) at the end of the SAT run to see if all runs have been finished successfully
